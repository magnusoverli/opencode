# Compact Home Assistant MCP Profile

The built-in `homeassistant` MCP server is in the **compact** profile. It exposes state, history, diagnostics, templates, calendars, focused home-context tools, bounded Supervisor health evidence, Supervisor app inspection and non-applying previews, and ESPHome device listing/troubleshooting. Use `get_home_context` before broad state listings. For ESPHome, use `esphome_list_devices` to obtain the exact filename and `esphome_troubleshoot` for objective DNS, mDNS, ICMP, or bounded crash-decoding evidence.

`supervisor_app_inspect` reads named app state and redacted options. `supervisor_app_preview` validates proposals and creates five-minute in-memory plans without saving or changing app lifecycle. Show the before/after review; withheld values are not unset. Application requires the full profile, an apply-capable agent and native permission approval. A restart loses pending previews, so inspect and preview again after changing profiles. `get_agent_capabilities.mcp` is the server catalogue; use its `current_agent` snapshot when available and treat `unknown` as unknown.

Do not attempt service calls, configuration writes or migration planning, firmware or system updates, screenshots, `hab`, or `zigporter` commands through this MCP server. If the user needs those capabilities, explain that they must select the `configuration` or `full` MCP tool profile in the OpenCode add-on Configuration tab and restart the add-on.
